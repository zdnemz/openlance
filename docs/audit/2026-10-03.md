# OpenLance audit — 2026-10-03

Committed together with the fixes (branch `audit-fixes`). The PoCs that proved
each attack live on as inverted regressions in `apps/contracts/test/audit-regressions.ts`.

**Scope.** The working tree at `53fcb1b` plus the uncommitted work: contracts, API,
web, deploy/serverless config, UX/a11y/perf.
**Bar.** Severity is graded as if the contracts held real funds; testnet impact
is noted where it differs.
**Method.** Flows traced end to end with CodeGraph. Contract findings are proven with
a failing Hardhat test where marked. Nothing ran against the hosted Supabase /
Upstash / Vercel.

| Severity | Meaning |
|---|---|
| Critical | Funds can be stolen or frozen, or auth can be bypassed, by an outsider |
| High | Funds or authority at risk under realistic conditions, or the service cannot run |
| Medium | Wrong state or broken guarantee a user will hit; abuse with bounded cost |
| Low | Defense-in-depth, edge-case UX dead ends, misleading config |
| Info | Worth knowing; no change required |

**CONFIRMED** = reproduced (test/script/build artifact) or certain from the code
path. **PLAUSIBLE** = the path exists but was not reproduced.

## Phase 0 — uncommitted work

### P0-1 · `pnpm dev` / `start` boot a file that no longer exists
- **High · CONFIRMED** · `apps/api/package.json:8-9`
- The WIP renamed `src/server.ts` → `src/serve.ts` (so Vercel does not treat it as a
  captured listener) and updated `scripts/stop.sh`, but `dev` and `start` still run
  `src/server.ts`. `pnpm dev`, `pnpm dev:api`, `pnpm start` and any VM/container
  host die with `Cannot find module …/src/server.ts`.
- **Fix:** point both scripts at `src/serve.ts`.

### P0-2 · A paid `switchRole` never reaches the mirror until the next sign-in
- **Medium · CONFIRMED** · `apps/api/src/chain/adapter.ts:119-146`, `apps/api/src/modules/users.ts:255`
- `fetchLogs` polls only the Escrow and ArbiterRegistry; nothing in the API reads
  `RoleRegistry` events. `users.role` is re-derived only in `syncRoleFromChain`, which
  runs at login. `switchRole` is a public function, so a wallet that pays to move
  client → freelancer keeps its old seat in every API check for the rest of its JWT
  lifetime, and `confirmRole` cannot re-mirror it (it refuses once KYC started).
  The intent doc's success line — "replay the event log → role comes back
  identical" — is unmet: role only comes back lazily, per wallet, at its next login.
- **Fix:** add the RoleRegistry address to `fetchLogs`' sources and ingest its
  claim/switch events into `users.role` (idempotent on tx+log index like the rest).

### P0-3 · The API's `maxDuration` is silently dropped
- **Low · CONFIRMED** · `apps/api/vercel.json:5`
- The `functions` key is `src/app.func` — a build-output directory name, not a source
  path. `vc build` passed it into the Hono builder (`.vercel/output/builds.json`), and
  the emitted `functions/index.func/.vc-config.json` has no `maxDuration`. The cron
  route runs on the plan default (10 s on Hobby without Fluid compute), not 60 s.
- **Fix:** key it by the entry source (`"src/app.ts"`) and check that
  `.vc-config.json` carries `"maxDuration": 60` after `vc build`.

### P0-4 · The cron bearer token is compared with `!==`
- **Low · CONFIRMED** · `apps/api/src/modules/cron.ts:120`
- The comment reasons about `timingSafeEqual`, but the code never calls it; a plain
  string compare exits at the first differing byte. Remote exploitation is
  impractical, but the sibling `inbound.ts:26` already does it right.
- **Fix:** keep the length check, then `timingSafeEqual(Buffer.from(token), Buffer.from(secret))`.

### P0-5 · A claimed seat whose mirror write fails can't be retried without a reload
- **Low · CONFIRMED** · `apps/web/app/(app)/onboarding/page.tsx` (`RoleStep.confirm`)
- `seat` is read once. After a successful `claim`, if `POST /users/me/role` fails —
  e.g. the API's RPC is a block behind the wallet's and answers `seat_not_claimed`,
  or any network error — the retry still sees `seat.state === "none"`, calls `claim`
  again, reverts `AlreadyClaimed`, and returns silently. The button is dead until reload.
- **Fix:** after a successful claim, set the local seat to `{ state: "claimed", role }`
  (or re-read `roleOf`) so a retry goes straight to the mirror write.

## Tier 1 — contracts and the API's money/auth paths

PoCs: `docs/audit/poc/contracts.poc.ts` — 12 tests, **12 passing** (a pass means the
attack works). Run from `apps/contracts`:
`npx hardhat test nodejs ../../docs/audit/poc/contracts.poc.ts`. The existing suite
is green (115 passing) — none of these paths are covered by it.

### C1 · A party picks its own judges; a silent judge refunds the client with no appeal
- **Critical · CONFIRMED (PoC C1)** · `apps/contracts/contracts/Escrow.sol:592-649` (`openDisputeWith`/`_startRound`), `:876-890` (`_tally` no-quorum branch)
- `openDisputeWith(id, preferred)` seats whatever eligible addresses the caller passes and
  calls the panel "BINDING". The "mutually agreed" panel exists only in Postgres
  (`projects.chosen_arbiters`); the contract never checks it. A one-name panel is a
  1-seat round that decides on 1 reveal. If nobody reveals, `_tally` refunds the client
  in full, marks the milestone `ResolvedRefund` (terminal — `appeal` reverts
  `NotDisputed`), and applies **no** score change to the silent arbiter.
- Scenario: freelancer submits 10 ETH of work → client calls
  `openDisputeWith(id, [myArbiter, 0, 0])` → waits 48 h → `resolveDispute` → 10 ETH back,
  freelancer has no recourse. The client needs one eligible arbiter it controls
  (0.1 ETH, refundable) — or just one it knows is inactive. The mirror image: a freelancer
  names a sybil that votes Release on an unworked `Funded` milestone; the client must
  notice and appeal inside the window.
- **Fix:** record the agreed panel on-chain (both parties sign an EIP-712 panel, verified
  in `openDisputeWith`; or a propose/accept pair per milestone) and seat only that.
  Penalise non-revealers in the no-quorum branch too (see H1 for what that branch should pay).

### C2 · Anyone can drain the arbiter reward pool
- **Critical · CONFIRMED (PoC C2)** · `Escrow.sol:985-1030` (`_distributeRewards`), `:360` (`fund`)
- Disputes are free (`disputeFee = 0` in `deploy.ts`) and every finalized dispute pays the
  panel `min(rewardPool, disputeReward)` (0.05 ETH). With C1's caller-chosen panel, an
  attacker funds a 1-wei milestone between two of its own wallets, names its own arbiter,
  votes Release, and collects 0.05 ETH per 1-wei dispute — all in parallel, since one
  arbiter can sit on any number of rounds. The PoC empties a 0.15 ETH pool with 3 wei.
- **Fix:** C1's on-chain panel removes the free choice; additionally scale the subsidy to
  the milestone (e.g. `min(disputeReward, amount * bps)`) or require a non-trivial
  minimum disputable amount.

### H1 · A silent appeal panel overturns a quorum ruling into a full client refund
- **High · CONFIRMED (PoC "unanimous ruling")** · `Escrow.sol:1094-1128` (`resolveAppeal` → `_tally`)
- The no-quorum fallback is the same in every round: refund the client. In an appeal it
  discards the previous round's quorum decision. A client who lost 3–0 appeals (free) and
  wins outright if ≥2 of the redrawn panel stay silent — and silence is unpunished (C1).
  The docstring at `:1111` still says a no-quorum appeal "returns the milestone to Submitted".
- **Fix:** a no-quorum appeal round should fall back to `d.settledOutcome` (the last
  quorum decision), and only round 0 should fall back to a refund.

### H2 · Appeals are free and unbounded
- **High · CONFIRMED (PoC "appeals cost nothing")** · `Escrow.sol:1045-1086`
- `appeal` requires `msg.value >= disputeFee` (0) and caps rounds only by `uint8` overflow
  (255). Each round is ≥ commit + reveal + appeal window (4 days on prod settings), so
  the losing party can hold a payment for years, re-rolling the draw every time — and
  every re-roll is another chance at H1's no-quorum refund. The PoC keeps a milestone
  `Disputed` through three unanimous Release rulings.
- **Fix:** cap appeals (1–2), and price them (escalating fee, forfeited on a loss).

### H3 · One majority arbiter that can't receive ETH freezes a settlement forever
- **High · CONFIRMED (PoC "rejects ETH")** · `Escrow.sol:962,1017` (`_pay` to arbiters), `:929` (`_pay` to the client on Split), `:1409-1413`
- `finalizeDispute` pushes ETH to every majority arbiter (and to the client on a split)
  and reverts the whole settlement on any failed transfer. Once the appeal window closes,
  `finalizeDispute` is the only exit; a contract wallet, an EIP-7702 delegate, or a
  deliberately reverting arbiter makes it revert forever. The PoC strands 10 ETH.
  A client contract can do the same to a Split it dislikes.
- **Fix:** credit arbiter fees/rewards (and split refunds) to a pull balance; push only
  where failure is harmless.

### H4 · The opener, not just the block producer, can choose the random draw
- **High at mainnet (Info on testnet) · PLAUSIBLE** · `Escrow.sol:704-708`
- The seed is `prevrandao, timestamp, milestoneId, round, msg.sender, client, freelancer` —
  all known when the opener submits. On Base, `prevrandao` follows the L1 origin and is
  known ahead; with EIP-7702 or a wrapper the opener can open-and-revert until the draw
  suits it, paying only for reverted attempts. The contract comment bounds the risk to
  "a biased producer"; that bound is wrong. (Documented design choice — VRF already
  planned for mainnet — flagged because the stated risk is understated.)

### M1 · `resolveDispute` tallies appeal rounds and skips the overturn penalty
- **Medium · CONFIRMED (PoC)** · `Escrow.sol:809-823`
- Nothing restricts `resolveDispute` to round 0. Calling it on an appeal round tallies
  the round without `resolveAppeal`'s −25 for the overturned panel — and makes
  `resolveAppeal` revert. Any overturned arbiter can front-run the honest call.
- **Fix:** `if (d.round != 0) revert` in `resolveDispute` (or share one tally entrypoint).

### M2 · (WIP) The appealed panel is released early enough to dodge the overturn penalty
- **Medium · CONFIRMED (PoC "WIP")** · `Escrow.sol:1081` (uncommitted)
- The WIP fix correctly stops round 0 from holding its seat forever, but releases it at
  `appeal` time. The overturn penalty lands only at `resolveAppeal`, ~2 days later; in
  between an arbiter seated only in round 0 can `requestUnstake` + `withdrawStake` and
  leave with full collateral and an untouched score (the penalty loop skips
  unregistered arbiters).
- **Fix:** release the superseded panel after the appeal round is tallied — in
  `resolveAppeal` after the overturn loop, and in the no-quorum branch for `round > 0`.

### M3 · The arbiter draw skips eligible arbiters
- **Medium · CONFIRMED (PoC: 3/12 rounds degraded)** · `Escrow.sol:710-731`
- `stride = seed % (len-1) + 1` is not forced coprime with `len`, so the walk revisits a
  subset (len 4, stride 2 → 2 of 4 slots). With 4 eligible arbiters, 3 of 12 rounds
  seated 2 instead of 3 — fewer judges, and more single-judge rounds on thin rosters.
- **Fix:** pick `stride` coprime with `len` (or a linear probe with stride 1 from a random start).

### M4 · Appeal fees are refunded to the wrong party, and earlier fees are stranded
- **Medium (latent while `disputeFee = 0`) · CONFIRMED (PoC)** · `Escrow.sol:1066`, `:879-882`
- `appeal` overwrites `d.fee`; the no-quorum branch refunds `d.fee` to `d.openedBy`. The
  client's appeal fee goes to the freelancer who opened, and the opener's own fee is no
  longer tracked anywhere — it stays in the contract forever.
- **Fix:** keep fees per round with their payer; refund/distribute per round.

### M5 · The "soulbound" arbiter badge is transferable
- **Medium · CONFIRMED (PoC)** · `apps/contracts/contracts/ArbiterRegistry.sol` (no `_update` override)
- `transferFrom` works; `locked(tokenId)` still returns true. SECURITY.md property 7 cites
  an `_update` revert and a test in `test/registry.ts`; neither exists. Eligibility reads
  the `arbiters` mapping, so money is not at risk — but anything showing "badge holder"
  as identity is spoofable.
- **Fix:** override `_update` to revert unless minting; emit `Locked` at mint (ERC-5192 —
  the code says ERC-5194).

### M6 · Forwarder sessions are neither owner-bound nor expiry-checked at execution
- **Medium · CONFIRMED (PoC)** · `apps/contracts/contracts/SponsorshipForwarder.sol:272-273`
- `registerSession` stores only `sessionUsed[id] = true`; `execute` checks that boolean.
  Expiry and owner are never consulted again — the `(expiry/owner were validated at
  registration)` comment is wrong, and README/SECURITY claims ("an expired session is
  rejected at the contract", "only a session signed by `req.from`") do not hold. The
  per-request signature still gates the sender, so this is a broken guarantee rather
  than a theft path.
- **Fix:** store `owner` + `expiry` per session; in `execute` require
  `owner == req.from && block.timestamp <= expiry`.

### M7 · `handoff-timelock.ts` cannot hand off, and its renounce path can brick the timelock
- **Medium · CONFIRMED (PoC)** · `apps/contracts/scripts/handoff-timelock.ts` (`schedule(..., 0n)`)
- Every grant is scheduled with delay `0`; OZ reverts `TimelockInsufficientDelay` for any
  `minDelay > 0`, so production stays a single deployer key. `RENOUNCE_DEPLOYER=1`
  renounces without checking `hasRole(…, FINAL_ADMIN)` — run before the grants execute,
  it leaves a timelock nobody can operate (fees and upgrades locked).
- **Fix:** schedule with `await timelock.read.getMinDelay()`; refuse to renounce until
  `FINAL_ADMIN` holds every role.

### A1 · Funding is mirrored on `ref` alone
- **High · CONFIRMED (code path)** · `apps/api/src/chain/indexer.ts:208-265` (`applyFunded`), `apps/api/src/modules/helpers.ts:95-155`, `apps/api/src/chain/adapter.ts:148-171`
- `MilestoneFunded` is matched to a milestone by `ref` only. `client` and `freelancer` are
  never compared to the project's wallets, and an amount mismatch is a `log.warn` — the
  row still flips to `funded`. `findFundingByRef` takes the *first* event for the ref.
  Anyone can emit that event (`fund(ref, …)` is permissionless).
- Scenarios: a client funds the award with `freelancers[i]` = its own alt wallet → the room
  shows "Funded", the freelancer works, `submit` reverts `NotFreelancer`; or anyone who
  learns a milestone uuid funds 1 wei first → the real funding is dropped as "already
  funded" and the project is wedged.
- **Fix:** accept a funding event only if `client`/`freelancer` equal the project's wallets
  and `amount == amountWei` (and, for credit funding, the job ref matches); otherwise
  record drift and keep looking for a valid event.

### A2 · Config fails open: public JWT secret, dev routes, auto-reset
- **High · CONFIRMED (code path)** · `apps/api/src/config.ts:18,48,180-185,234`, `apps/api/src/routes/dev/stack/route.ts:27`
- `SUPABASE_JWT_SECRET` defaults to a string committed in the repo; in production the
  check only `console.error`s and boots anyway. Anyone can then mint a session for any
  user id (admins included). Worse, if *any* env var fails validation, `schema.parse({})`
  silently replaces the whole config with defaults: `NODE_ENV=development`, the public
  secret, mock chain. `NODE_ENV` itself defaults to `development`, so a VM started with
  `pnpm start` exposes `POST /api/dev/stack` (unauthenticated; spawns `dev-real.sh`, which
  rewrites `.env.local` and pushes the schema) and lets the indexer auto-wipe the mirror on
  an address change.
- **Fix:** refuse to boot on invalid env or a default/short secret outside
  `development`; gate dev routes on an explicit `ENABLE_DEV_ROUTES=1` (or don't mount them).

### A3 · The relayer pays for any call, to any contract, with any gas
- **High at mainnet (Medium on testnet) · CONFIRMED (code path)** · `apps/api/src/modules/sponsorship.ts:255-331,451-525`
- The only server checks are: authenticated, `from` = caller, `value == 0`, unexpired
  session, 60/hour/user. `to`, `data` and `gas` (no cap, default 1M) are free. Any wallet
  can sign in, so the per-user cap does not bound a sybil drain, and one request can burn
  up to the block gas limit of the relayer's ETH. On testnet, draining the relayer turns
  gasless off for everyone.
- **Fix:** allow-list `to` (escrow/registry/role registry) and the sponsored selectors;
  cap `gas`; require KYC (or a claimed seat) for sponsorship; add a global hourly budget.

### A4 · A published job can be re-published on an old deposit hash
- **Medium · CONFIRMED (code path)** · `apps/api/src/modules/jobs.ts:133-175`
- `verifyDeposit` validates the *transaction* (from poster, to escrow, value, `lockBudget`
  for this ref), not the current lock. After `unlockBudget`, the indexer moves the job to
  draft and clears `deposit_tx_hash`; re-publishing with the same hash passes, and the
  marketplace shows an unfunded job as escrow-backed until the nightly reconcile — after
  which it can be replayed again.
- **Fix:** verify live state (`budgetLocker == poster`, free budget ≥ ceiling), or record
  consumed hashes with a unique index.

### A5 · The indexer and the funding lookup assume a young chain
- **Medium (blocks a Base Sepolia launch) · CONFIRMED (code path)** · `apps/api/src/chain/indexer-pump.ts:106-107`, `apps/api/src/chain/adapter.ts:151-157`
- A fresh checkpoint starts at block 1, so on Base Sepolia (tens of millions of blocks)
  the pump makes ~2 × (height / 2000) `eth_getLogs` calls before reaching the deploy
  block — hours of cron ticks and a public-RPC rate-limit magnet. `findFundingByRef`
  asks for `0 → latest` in one call, which hosted RPCs reject for range size; the
  `.catch(() => [])` turns that into "never funded", so resolve-on-write and the
  reconcile backfill silently never work. `fetchLogs` also makes one `getBlock` per log.
- **Fix:** `INDEXER_START_BLOCK` (= deploy block, written by `deploy.ts`); chunk
  `findFundingByRef` from that block; cache block timestamps per chunk.

### A6 · Supabase tables may be reachable through the Data API
- **High if confirmed · PLAUSIBLE** · `apps/api/src/db/schema.ts` (all `pgTable` in `public`), `apps/api/drizzle/0006_…sql:1` (`DISABLE ROW LEVEL SECURITY`)
- Every table lives in `public` with RLS off (one migration even disables it), and the
  API's session JWTs are signed with the project's JWT secret with
  `role: 'authenticated'`. Supabase's default grants give `anon`/`authenticated` full
  table access, and its anon/publishable key is designed to be public, so the database
  — sessions, webhook secrets, messages — is one leaked key away from PostgREST
  read/write. I did not touch the hosted project; check
  *Dashboard → Advisors → Security* ("RLS disabled in public").
- **Fix:** `ENABLE ROW LEVEL SECURITY` on every table with no policies (the API connects
  as `postgres` and bypasses RLS), or revoke `anon`/`authenticated` on `public`.

### Lower-severity contract and auth notes
- **L1 · Low · PLAUSIBLE** — First `lockBudget`/`fundAllFromCredit` on an unused `jobRef`
  wins it for good (`Escrow.sol:385-392,435-442`); a front-runner who sees the ref can
  squat a job's key for gas. Base has no public mempool; L1 does.
- **L2 · Low · CONFIRMED (code)** — `commitVote` accepts a zero hash (`Escrow.sol:765-768`):
  the arbiter can "commit" twice and inflate `commitCount`, and can never reveal.
- **L3 · Low · CONFIRMED (code)** — The appeal window counts from the reveal deadline, not
  the tally (`Escrow.sol:840,1061`): a tally made late enough is finalizable in the same
  block, with zero time to appeal.
- **L4 · Low · CONFIRMED (code)** — A slashed (score 0) arbiter can re-register
  (`ArbiterRegistry.sol:566-590`); the new stake is then locked forever (score < floor).
- **L5 · Low · PLAUSIBLE** — The forwarder does not check forwarded gas (EIP-150 1/64);
  Escrow treats failed registry staticcalls as "not eligible / not registered", so a
  starved relay can change selection and skip scoring. Only the relayer (or anyone holding
  a signed request) can do it.
- **L6 · Low · CONFIRMED (code)** — `/api/rpc` is mounted in every environment, open and
  unlimited; `GET` returns the upstream URL, which would leak an RPC key if `ANVIL_RPC_URL`
  ever points at a hosted node (`apps/api/src/routes/rpc/route.ts`).
- **L7 · Low · CONFIRMED (code)** — Rate limits key on the first `X-Forwarded-For` hop
  (`apps/api/src/lib/rate-limit.ts:84-86`): fine behind Vercel/Caddy, spoofable if the
  Node server is exposed directly.
- **L8 · Low · PLAUSIBLE** — The relayer reuses one key with no nonce coordination; on
  serverless, concurrent relays race for nonces and fail intermittently.
- **Info** — `slither.config.json` is YAML in a `.json` file: Slither prints "Impossible to
  read slither.config.json" and runs with no excludes, so the documented exclusion set has
  never applied (a fresh run reports `weak-prng`, `reentrancy-eth` on `rewardPool += dust` —
  benign, `finalizeDispute` is `nonReentrant` — and `arbitrary-send-eth` on the forwarder).
  `ArbiterRegistry.slash`/`slashStake` are unused (and `slash` would orphan stake on
  re-enroll). `DisputeResolved` logs `msg.sender`, i.e. the forwarder on relayed calls.
  The overturn penalty hits every seated arbiter, not just the majority (already "Open" in `docs/escrow.md`).

## Tier 2 — rest of the API, web, deploy, dependencies

### A7 · A dispute opened straight from a wallet is invisible to its arbiters
- **High · CONFIRMED (code path)** · `apps/api/src/chain/indexer.ts:455-501`, `apps/api/src/modules/disputes.ts:126-160`
- The dispute row is created only by `POST /disputes`. If a party calls
  `Escrow.openDispute` from its wallet, `ArbitersSelected` and every vote event are dropped
  as DRIFT (no row), `listDisputes` (built from rows) never lists it, and no
  `dispute.opened` notification is sent. The drawn arbiters never learn they were seated
  → nobody reveals → no-quorum → full client refund. This makes C1 work with a *random*
  panel and no sybil. Also: `listDisputes` takes the platform's newest 200 rows *before*
  filtering by viewer (older open disputes vanish for everyone), and live-reads 2 RPC calls
  per open dispute on every request.
- **Fix:** create the dispute row from `DisputeOpened` when missing and notify on
  `ArbitersSelected`; filter by viewer in SQL; cache the overlay.

### T2-1 · Arbiters cannot see the evidence they rule on
- **Medium · CONFIRMED (code path)** · `apps/api/src/modules/submissions.ts:107`, `chat.ts:30`, `files.ts:175`
- Submissions, chat and attachment downloads all use `requireParticipant`; only the
  project room read uses `requireParticipantOrArbiter`. Seated arbiters get 403 on the
  delivery notes, the files and the conversation.
- **Fix:** use `requireParticipantOrArbiter` (seated or selected) for those three reads.

### T2-2 · A confirmed upload can be silently replaced
- **Medium · CONFIRMED (code path)** · `apps/api/src/modules/files.ts:186-203`
- `PUT /files/:id/raw` has no status check and Supabase uploads with `upsert: true`, so the
  uploader can swap a delivered file or dispute evidence after the other side (or an
  arbiter) reviewed it. No content hash is recorded.
- **Fix:** refuse writes once `status = 'confirmed'`; store a SHA-256 at confirm.

### T2-3 · Webhooks are an SSRF primitive
- **Medium · CONFIRMED (code path)** · `apps/api/src/modules/webhooks.ts:43-58`, `apps/api/src/workers/webhooks.ts:197`
- Any `http(s)` URL is accepted (localhost, 10/8, 169.254.169.254, `:8545`), `fetch`
  follows redirects, and `lastStatusCode`/`lastError` ("ECONNREFUSED 127.0.0.1:5432") are
  readable via `listDeliveries` — an internal port scanner, triggerable on demand with
  `/test`.
- **Fix:** resolve and reject private/link-local ranges, `redirect: 'manual'`, store a
  generic error.

### Lower-severity Tier 2 notes
- **Low** — `putAttachmentRaw` buffers the whole body before the size check (memory DoS on a
  VM host; Vercel caps bodies at 4.5 MB); declared `sizeBytes` is never compared to the bytes.
- **Low** — `/api/ledger` and `/ledger/summary` are unauthenticated full-table scans
  (summary reads `ledger_events` twice per call); `listJobs` passes `q` to `ILIKE` without

### T2-4 · The public overview publishes the newest project's milestone ids
- **Medium · CONFIRMED (code path)** · `apps/api/src/modules/overview.ts:180-200`
- `GET /api/overview` needs no auth and returns the newest project with both parties'
  wallets and names and every milestone's `id`, title and amount. Those ids are the
  on-chain `ref`s. Right after an award, before the client's funding lands, an outsider
  polling `/overview` can fund 1 wei under each ref and poison the mirror (A1). This is
  also a privacy leak of a private engagement.
- **Fix:** drop `demoProject` (or serve it only in mock/dev).

### T2-5 · The browser signs whatever `/relay/prepare` sends back
- **Medium · CONFIRMED (code path)** · `apps/web/lib/sponsorship.ts:45-68`
- The client encodes `data` itself, then signs `prepared.request.to/data/value/gas` and
  `prepared.domain` from the server's response without comparing them. A compromised or
  misconfigured API gets a valid signature for any call, e.g. `fundFromCredit(jobRef, ref,
  attacker, amount)` from the client's locked budget — zero-value, so relayable. The
  wallet shows raw calldata hex.
- **Fix:** assert `request.from == wallet`, `to == opts.to`, `data == encoded`,
  `value == requested` and `domain.verifyingContract == runtime forwarder` before signing.

### T2-6 · Anvil is reachable from the internet on any anvil-backed deploy
- **High on a public anvil/preview box (Info on Vercel + Base Sepolia) · CONFIRMED (config)** · `Caddyfile:20-26`, `apps/api/src/routes/rpc/route.ts`
- The Caddy `:81` site proxies `?XTransformPort=<n>` to `localhost:<n>` for anyone: every
  local port is public. `/api/rpc` forwards any JSON-RPC to anvil without auth or a method
  filter. Anvil's dev accounts are unlocked (they include the deployer, i.e. timelock
  proposer/executor/admin) and its `anvil_setCode` / `anvil_impersonateAccount` /

  chain. (Upgrades L6.)
- **Fix:** delete the `XTransformPort` handler; mount `/api/rpc` only in development and
  allow-list read methods plus `eth_sendRawTransaction`.
